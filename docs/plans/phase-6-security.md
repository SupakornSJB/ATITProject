## What This Phase Adds

A single security addition: **mutual TLS on the embedded Kestrel gRPC server**.

Currently the Unity gRPC server accepts any connection on port 9090 and validates
a shared secret string in the request metadata. Phase 6 replaces this with proper
mutual TLS — Unity presents a server certificate, and ASP.NET must present a valid
client certificate signed by the project CA. The TLS handshake itself is the
authentication — no more header-based secret.

---

## Threat Model (Unity Layer)

| Threat | Before Phase 6 | After Phase 6 |
|---|---|---|
| Anyone reaching port 9090 can send gRPC events | ⚠️ Shared secret only | ❌ No valid client cert → TLS rejected |
| Shared secret leaked from config | ⚠️ Anyone can craft gRPC calls | ❌ Cert required — secret alone insufficient |
| Man-in-the-middle on ASP.NET → Unity channel | ⚠️ HTTP/2 but no server cert validation | ❌ Both sides validate each other's cert |

## Certificate Setup

Unity needs two files on disk at runtime:

| File | Purpose | Source |
|---|---|---|
| `unity-server.crt` | Unity's server certificate (presented to ASP.NET) | Generated by `gen_device_cert.sh unity-server` |
| `unity-server.key` | Unity's server private key | Generated by same script |
| `ca.crt` | CA certificate (to validate ASP.NET client cert) | From `firmware/certs/ca.crt` |

Generate from the firmware repo:
```bash
# In ATITFinalProject-firmware/
./scripts/gen_device_cert.sh unity-server

# Copy to Unity project
cp certs/unity-server/device.crt path/to/unity/Certs/unity-server.crt
cp certs/unity-server/device.key path/to/unity/Certs/unity-server.key
cp certs/ca.crt                   path/to/unity/Certs/ca.crt
```

## `GrpcServerHost.cs` — Mutual TLS Kestrel Configuration

Replace the current plain HTTP/2 Kestrel setup with a TLS-enabled configuration
that presents a server certificate and requires a client certificate from ASP.NET.

```csharp
public static class GrpcServerHost
{
    private static IHost?              _host;
    private static CancellationTokenSource? _cts;

    public static void Start(int port, string certPath, string keyPath, string caCertPath)
    {
        _cts = new CancellationTokenSource();

        _host = Host.CreateDefaultBuilder()
            .ConfigureWebHostDefaults(web =>
            {
                web.UseKestrel(kestrel =>
                {
                    kestrel.ListenAnyIP(port, listenOpts =>
                    {
                        listenOpts.UseHttps(https =>
                        {
                            // Load Unity server certificate
                            https.ServerCertificate = LoadCertWithKey(certPath, keyPath);

                            // Require ASP.NET to present a client certificate
                            https.ClientCertificateMode =
                                ClientCertificateMode.RequireCertificate;

                            // Validate client cert against our CA
                            https.ClientCertificateValidation = (cert, chain, errors) =>
                            {
                                if (cert == null) return false;

                                var caCert = new X509Certificate2(caCertPath);
                                using var customChain = new X509Chain();
                                customChain.ChainPolicy.TrustMode =
                                    X509ChainTrustMode.CustomRootTrust;
                                customChain.ChainPolicy.CustomTrustStore.Add(caCert);
                                customChain.ChainPolicy.RevocationMode =
                                    X509RevocationMode.NoCheck;

                                bool valid = customChain.Build(
                                    new X509Certificate2(cert));

                                if (!valid)
                                    Debug.LogWarning(
                                        $"[gRPC] Client cert rejected: " +
                                        $"{string.Join(", ", customChain.ChainStatus.Select(s => s.StatusInformation))}");

                                return valid;
                            };
                        });

                        listenOpts.Protocols = HttpProtocols.Http2;
                    });
                });

                web.ConfigureServices(services =>
                {
                    services.AddGrpc();
                });

                web.Configure(app =>
                {
                    app.UseRouting();
                    app.UseEndpoints(endpoints =>
                    {
                        endpoints.MapGrpcService<IoTGameServiceImpl>();
                    });
                });
            })
            .Build();

        Task.Run(() => _host.RunAsync(_cts.Token));
        Debug.Log($"[gRPC] Server started with mTLS on port {port}");
    }

    public static void Stop()
    {
        _cts?.Cancel();
        _host?.Dispose();
    }

    // Load certificate + separate private key file (PEM format)
    private static X509Certificate2 LoadCertWithKey(string certPath, string keyPath)
    {
        // Load cert and key from separate PEM files
        var cert    = X509Certificate2.CreateFromPemFile(certPath, keyPath);
        // On Windows, copy private key to make it usable by Kestrel
        return new X509Certificate2(cert.Export(X509ContentType.Pfx));
    }
}
```

> **IL2CPP note:** `X509Certificate2.CreateFromPemFile` requires .NET 5+.
> Unity 2022.3 LTS with the .NET Standard 2.1 scripting runtime supports this.
> Add to `link.xml`:
> ```xml
> <assembly fullname="System.Security.Cryptography.X509Certificates" preserve="all"/>
> ```

## `ServerBootstrap.cs` — Parse Cert Path CLI Arguments

Add cert path arguments alongside the existing `-grpcPort` and `-gamePort` args:

```csharp
void Start()
{
    var args = System.Environment.GetCommandLineArgs();

    int    grpcPort   = GetArgInt(args,    "-grpcPort",   9090);
    int    gamePort   = GetArgInt(args,    "-gamePort",   7777);
    string certPath   = GetArgString(args, "-grpcCert",   "Assets/Certs/unity-server.crt");
    string keyPath    = GetArgString(args, "-grpcKey",    "Assets/Certs/unity-server.key");
    string caCertPath = GetArgString(args, "-caCert",     "Assets/Certs/ca.crt");

    // Start NGO
    NetworkManager.Singleton.GetComponent<UnityTransport>()
        .SetConnectionData("0.0.0.0", (ushort)gamePort);
    NetworkManager.Singleton.StartServer();

    // Start gRPC with mTLS
    GrpcServerHost.Start(grpcPort, certPath, keyPath, caCertPath);

    Debug.Log($"[Bootstrap] gRPC mTLS on :{grpcPort}, NGO on :{gamePort}");
}

void OnDestroy()
{
    GrpcServerHost.Stop();
}

private static int GetArgInt(string[] args, string flag, int defaultVal)
{
    int idx = Array.IndexOf(args, flag);
    return idx >= 0 && idx + 1 < args.Length
        ? int.TryParse(args[idx + 1], out int v) ? v : defaultVal
        : defaultVal;
}

private static string GetArgString(string[] args, string flag, string defaultVal)
{
    int idx = Array.IndexOf(args, flag);
    return idx >= 0 && idx + 1 < args.Length ? args[idx + 1] : defaultVal;
}
```

## `IoTGameServiceImpl.cs` — Remove Shared Secret Validation

The `ValidateSecret()` call is removed entirely. Authentication is now handled
by the TLS handshake — if ASP.NET reaches the gRPC service method, its client
cert has already been validated by Kestrel.

```csharp
// REMOVE this method entirely:
// private void ValidateSecret(ServerCallContext context) { ... }

// REMOVE calls to ValidateSecret() from all RPC methods:
public override Task<InputEventResponse> SendInputBatch(
    InputBatchRequest request, ServerCallContext context)
{
    // ValidateSecret(context);  ← REMOVED
    InputQueue.Enqueue(request);
    return Task.FromResult(new InputEventResponse { Accepted = true });
}

// Same for SendEnvironmentEvent and SendAdminCommand
```

## Demo: Attack 3 — Unauthorised gRPC Call

The Python rogue script (`ATITFinalProject-firmware/tools/rogue_device.py`) can be
extended to demonstrate a gRPC connection attempt without a valid client cert.
The TLS handshake fails before any gRPC message is sent.

Alternatively, use `grpcurl` with no client cert:

```bash
# Should fail with TLS handshake error — no client cert
grpcurl -plaintext localhost:9090 list

# Should also fail — server requires TLS
grpcurl -insecure localhost:9090 list
```

Both commands fail before reaching any gRPC service code — proof that Kestrel
enforces mutual TLS at the transport layer independently of application logic.
