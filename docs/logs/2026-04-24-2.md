## Phase 2 Implementation

### Proto
New file: `Proto/game_controller_v2.proto`
- Package: `game_controller.v2`, namespace: `GameController.V2`
- Service: `SendInputEvent` (single event) + `SendInputBatch` (batched)
- `InputEventRequest`: player_id, device_id, input_name, input_type, event_type, value (float 0–1), timestamp, sequence_number
- `InputBatchRequest`: repeated `InputEventRequest`
- `InputEventResponse`: accepted, message

Generated stubs with:
```powershell
protoc \
  --csharp_out=Assets/Scripts/Generated \
  --grpc_out=Assets/Scripts/Generated \
  "--plugin=protoc-gen-grpc=$env:USERPROFILE/.nuget/packages/grpc.tools/2.80.0/tools/windows_x64/grpc_csharp_plugin.exe" \
  --proto_path=Proto \
  Proto/game_controller_v2.proto
```
Output: `Assets/Scripts/Generated/GameControllerV2.cs` + `GameControllerV2Grpc.cs`

### New files
- `Assets/Scripts/Players/PlayerInputState.cs` — plain C# struct; `Dictionary<string, float>` keyed by inputName; `Get/Set/IsPressed` helpers
- `Assets/Scripts/Managers/PlayerInputStateRegistry.cs` — `NetworkSingleton`; owns per-player `PlayerInputState`; tracks last sequence number per deviceId for gap detection; `RemovePlayer` called on disconnect

### Updated files

**`IoTGameServiceImpl.cs`** — now implements v2 service (`GameController.V2.GameControllerService.GameControllerServiceBase`):
- Queue type changed from `ConcurrentQueue<ButtonInputEvent>` to `ConcurrentQueue<InputBatchEnvelope>`
- `SendInputEvent` wraps the single event in a one-item batch envelope
- `SendInputBatch` wraps the full repeated field as a batch envelope
- Both enqueue atomically; no Unity API calls

**`IoTInputManager.cs`** — drains new queue:
- For each envelope → for each event: update `PlayerInputStateRegistry`, check sequence gap, dispatch to `PlayerBird`
- `button/pressed` → `bird.OnButtonPressed(inputName)`
- `button/released` → `bird.OnButtonReleased(inputName)`
- `knob/sensor` → `bird.OnAnalogChanged(inputName, value)`

**`PlayerBird.cs`** — Phase 2 input interface:
- Removed direct `Flap()` call path (now goes through `OnButtonPressed("jump")`)
- Added `OnButtonPressed(string)`, `OnButtonReleased(string)`, `OnAnalogChanged(string, float)`
- `"jump"` → set Y velocity to flapForce (preserves X velocity)
- `"speed"` → store as `_currentHorizontalInput`; applied in `FixedUpdate()` as horizontal force
- New `NetworkVariable<float> HorizontalSpeed` — synced to clients for visual feedback
- `FixedUpdate()` applies sustained horizontal force from knob value

**`GrpcServerHost.cs`** — updated service registration to `GameController.V2.GameControllerService`

**`BirdSpawnManager.cs`** — `OnClientDisconnected` now also calls `PlayerInputStateRegistry.Instance?.RemovePlayer(playerId)`

## Breaking Change Note

The gRPC contract changed from `game_controller` (v1) to `game_controller.v2`.
The ASP.NET relay server (`/server`) must be updated to use `game_controller_v2.proto`
and call `SendInputBatch` / `SendInputEvent` instead of `SendButtonEvent`.
