## Death Detection — Position Check Instead of Trigger Collider

Initially implemented a `DeathBarrier` MonoBehaviour using a trigger collider.
Replaced with a Y-position check in `PlayerBird.FixedUpdate()` — simpler, no scene
object needed, and avoids physics layer/collider setup.

`_deathY` is a serialized field (default `-10`) tunable in the Inspector.

```csharp
// In PlayerBird.FixedUpdate():
if (transform.position.y < _deathY)
    Die();
```

`Die()` calls `BirdSpawnManager.HandleBirdDeath(playerId)` which despawns the
NetworkObject. Bird respawns on the next button press from that player.

`DeathBarrier.cs` was created then superseded — delete it if it still exists in the project.

## In-Game Debug Console UI

**Problem:** Inputs arrive on the server; clients had no visibility into what was
being received.

**Solution:** `[ClientRpc]` on `IoTInputManager` broadcasts each processed input to
all connected clients. `DebugConsoleUI` displays the last N lines in a UI panel.

### New file: `Assets/Scripts/UI/DebugConsoleUI.cs`
- `static Instance` for easy access from the ClientRpc
- `AddMessage(string)` — enqueues timestamped line, trims to `_maxLines` (default 12)
- Requires a `TextMeshProUGUI` reference wired in the Inspector

### Scene setup (do once in Unity Editor)
1. Create **UI → Canvas** in SampleScene
2. Add **UI → Panel** inside it (anchor to a corner, semi-transparent)
3. Add **UI → Text - TextMeshPro** inside the Panel
4. Attach `DebugConsoleUI` to the Panel; wire the TMP text into **Log Text**

### ClientRpc in `IoTInputManager`
```csharp
[ClientRpc]
private void NotifyInputClientRpc(string playerId, string inputName, string eventType, float value)
{
    UI.DebugConsoleUI.Instance?.AddMessage($"{playerId} | {inputName} | {eventType} | {value:F2}");
}
```

**Bug fixed:** The RPC call was originally placed after the bird lookup, so inputs
for unregistered players were silently dropped from the UI. Moved the log + RPC call
to before the bird lookup so every received event is always visible.

## Architecture Change — Server-Owned Birds, No Unity Client Required Per Player

**Old model:** A `PlayerBird` NetworkObject was spawned when a Unity NGO client
connected. `SpawnWithOwnership(clientId)` tied the bird to an NGO client.
If no client connected for a given `playerId`, that player's gRPC inputs were
silently ignored with "client not connected".

**New model:** Birds are server-owned (`netObj.Spawn()`). They are spawned lazily
on first gRPC input for a given `playerId`. No Unity client needs to exist for a
player — Unity clients are pure spectators.

### Changes

**`BirdSpawnManager`** — major rework:
- Removed `_clientToPlayer`, `_playerToClient` — no longer needed
- Removed `RegisterApprovedPlayer` — slot/color now assigned lazily in `EnsurePlayerSlot()`
- `SpawnBirdForPlayer(playerId)` calls `netObj.Spawn()` instead of `SpawnWithOwnership`
- `EnsurePlayerSlot(playerId)` — idempotent; assigns spawn X position and color on first call
- `OnClientDisconnected` now empty — disconnecting spectators have no birds to clean up

**`IoTInputManager`** — simplified spawn path:
- Removed `IsPlayerRegistered` check and "client not connected" warning
- Now just calls `SpawnBirdForPlayer(playerId)` unconditionally before bird lookup
  (`SpawnBirdForPlayer` is idempotent — does nothing if bird already alive)

**`ConnectionApprovalHandler`** — simplified to spectator-only approvals:
- Removed `KnownPlayerIds` allowlist — any client with a valid UTF-8 payload is approved
- Removed `ConnectedPlayerIds` duplicate check
- Removed `BirdSpawnManager.Instance.RegisterApprovedPlayer(...)` call
- `ReleasePlayer` is now a no-op
