## Phase 3.2 — Gravity / Spawn Rate Swap

Swapped which DHT11 output drives which game effect, based on real hardware behavior:
- DHT11 temperature (slow-changing) → `GlobalGravity` (ambient world parameter)
- DHT11 humidity (fast-changing) → minion spawn rate (dynamic, visible immediately)

**Changes:**
- `EnvironmentController.OnEnvironmentUpdate`: handles `"gravity"` and `"spawn_rate"` keys instead of `"temperature"` / `"humidity"`
- `ApplyGravityEffect`: lerps gravity 40→20 over 15–40°C (hot = floaty, cold = heavy)
- `ApplySpawnRateEffect`: lerps interval 8→1.5s over 30–90% humidity
- Threshold callouts: "MINION SURGE" at 70%+, "SWARM THINNING" below 50%
- `GlobalGravity` default set to **30** (user request — snappier feel)
- Gravity centralized: `EnvironmentController.FixedUpdate` applies to all registered Rigidbodies; `BossEnemyBird`, `EnemyBird`, `Projectile` each register on spawn
- `EnemySpawnManager`: Zone D frenzy now checks `UltrasonicZone.Value == 4` live each frame instead of a timed frenzy flag
- Setup doc: `Setup/UNITY_SETUP_PHASE_3_2.md`

## Problems Hit and How They Were Solved

### Input System error — `UnityEngine.Input.GetKeyDown`
**Problem:** `RoundUIManager` used legacy `Input.GetKeyDown(KeyCode.F4)` but project uses new Input System package.
**Fix:** Replaced with `Keyboard.current.f4Key.wasPressedThisFrame` from `UnityEngine.InputSystem`.

### UI scripts compiled into server build
**Problem:** Dedicated server build compiled `RoundUIManager` and `DebugConsoleUI`, causing `UnityEngine.InputSystem` and TMP references to fail.
**Fix:** Wrapped both UI files in `#if !UNITY_SERVER`. Guarded all `ShowCalloutClientRpc` call sites in `CalloutManager` and `IoTInputManager` with `#if !UNITY_SERVER`.

### `RoundUIManager` CS8967 — newline in interpolated string
**Problem:** Multi-line switch expression inside `$"..."` is not valid in C# 9.0.
**Fix:** Extracted switch to a local `string zoneLabel` variable before interpolation.

### `SendEnvironmentEvent` gRPC Unimplemented
**Problem:** ASP.NET server called `SendEnvironmentEvent` as a dedicated gRPC RPC, but Unity's service only had `SendInputEvent` and `SendInputBatch`. Unity returned `StatusCode=Unimplemented`.
**Initial approach:** Manually wrote `EnvironmentEventRequest.cs` and `GameControllerV2Extension.cs` (partial class extensions) as a workaround.
**Proper fix:** Updated `Proto/game_controller_v2.proto` to add `SendEnvironmentEvent` RPC and `EnvironmentEventRequest` message. Ran protoc from the NuGet cache (not on PATH — required `& "path\protoc.exe" --%  --flags...` syntax in PowerShell 5.1). Deleted manual files, reverted `GrpcServerHost` to standard `BindService`.

### `CalloutManager` — NetworkBehaviour not spawned crash
**Problem:** `ShowCalloutClientRpc` was called before `CalloutManager`'s `NetworkObject` was spawned (manager not yet in the scene). NGO throws `RpcException: NetworkBehaviour must be spawned before calling this method`.
**Fix:** Added `TryShowCallout(string, float)` wrapper that checks `IsSpawned` before calling the ClientRpc. Replaced all 16 call sites with `TryShowCallout`.

### `CheckWinConditions` fires immediately — false "BIRDS WIN"
**Problem:** `GameRoundManager.CheckWinConditions` ran in `Active` phase before any entities were spawned. With empty dictionaries, `IsShipAlive` and `IsBossAlive` both returned `false` for all players, incorrectly triggering a win.
**Fix:** Added `HasAnyShip()` and `HasAnyBossBird()` to `BirdSpawnManager`. `CheckWinConditions` now guards with `!HasAnyShip() || !HasAnyBossBird() → return`.

### Game ends immediately on first play — boss bird falls too fast
**Problem:** Default gravity=30, boss bird spawns at Y=5, `_bottomY=-10`. Time to fall = ~1 second. Bird players cannot react fast enough without constant button presses.
**Fix:** Increased `BossEnemyBird._flapForce` 5→15 and `_bottomY` -10→-20. One flap now buys ~1.5 seconds of air time.

### Falling off / pipe collision = instant death too harsh
**Problem:** Boss bird falling below `_bottomY` immediately triggered "BIRDS WIN". No mechanic for pipe damage.
**Fix:** Falling now deals `_fallDamage` (25 HP) and teleports the bird back to its spawn position. Pipe collision deals `_pipeDamage` (10 HP) via `OnCollisionEnter` with a 0.5s cooldown. Elimination only happens at 0 HP.

### Multiple prefabs / wrong positions on second round
**Problem:** Ships and boss birds were never despawned on round reset. On the next round, `SpawnForPlayer` found them in the dictionary (idempotent check) and skipped spawning. Entities remained at wrong positions from the previous round.
**Fix:** Added `BirdSpawnManager.DespawnAllPlayerEntities()` which despawns and clears both `_ships` and `_bossBirds`. Called in `GameRoundManager.TransitionTo(Waiting)`.

### Ready-up required all 4 players
**Problem:** `CheckAllReady` required all four players ready before countdown started, making testing with fewer players impossible.
**Fix:** Changed to one-per-side: `(Ship1Ready || Ship2Ready) && (Bird1Ready || Bird2Ready)`.
