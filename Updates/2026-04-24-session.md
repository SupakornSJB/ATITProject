## Proto Stub Generation

**Tool used:** `protoc` + `grpc_csharp_plugin` from `Grpc.Tools` NuGet package

```powershell
# Install Grpc.Tools to get grpc_csharp_plugin.exe
cd grpc-extractor
dotnet add package Grpc.Tools
dotnet restore

# Check version
ls "$env:USERPROFILE\.nuget\packages\grpc.tools\"

# Generate stubs (run from ATITProject root)
mkdir -Force Assets/Scripts/Generated
protoc --csharp_out=Assets/Scripts/Generated `
       --grpc_out=Assets/Scripts/Generated `
       --plugin=protoc-gen-grpc="$env:USERPROFILE\.nuget\packages\grpc.tools\<version>\tools\windows_x64\grpc_csharp_plugin.exe" `
       --proto_path=Proto `
       Proto/game_controller.proto
```

Output: `Assets/Scripts/Generated/GameController.cs` and `GameControllerGrpc.cs`

## gRPC DLL Setup — Full Journey

### Attempt 1: NuGetForUnity
- Installed `com.github-glitchenzo.nugetforunity` via Package Manager
- Searched for `Grpc.AspNetCore` in NuGet window
- **FAILED:** `Grpc.AspNetCore 2.76.0` requires `net8.0/net9.0/net10.0` — no `netstandard` build; NuGetForUnity can't install it

### Attempt 2: Manual extract with `--self-contained false`
```powershell
mkdir grpc-extractor && cd grpc-extractor
dotnet new console -f net9.0   # net8.0 not available; SDK has net9.0 and net10.0
dotnet add package Grpc.AspNetCore
dotnet publish -c Release --self-contained false -o ./out
```
- Result: only got `Google.Protobuf.dll`, `Grpc.AspNetCore.Server.dll`, `Grpc.Core.Api.dll`, `Grpc.Net.Common.dll`, `Grpc.Net.Client.dll`, `Grpc.Net.ClientFactory.dll`
- **Missing:** All `Microsoft.AspNetCore.*` and `Microsoft.Extensions.*` (framework-provided, not copied with `--self-contained false`)

### Attempt 3: `--self-contained true -r win-x64`
```powershell
dotnet publish -c Release --self-contained true -r win-x64 -o ./out
```
- Got `Microsoft.AspNetCore.*` and `Microsoft.Extensions.*` DLLs
- **FAILED:** All showed as **Type: Native** in Unity Inspector — ReadyToRun compiled (native+IL mixed); Unity misidentifies them

### Attempt 4: Reference assemblies from .NET SDK
```powershell
$ver = (ls "C:\Program Files\dotnet\packs\Microsoft.AspNetCore.App.Ref\" | Select -Last 1).Name
Copy-Item "C:\Program Files\dotnet\packs\Microsoft.AspNetCore.App.Ref\$ver\ref\net9.0\Microsoft.AspNetCore.*.dll" "Assets\Plugins\grpc\"
Copy-Item "C:\Program Files\dotnet\packs\Microsoft.AspNetCore.App.Ref\$ver\ref\net9.0\Microsoft.Extensions.*.dll" "Assets\Plugins\grpc\"
```
- DLLs showed as **Type: Managed** ✓
- **FAILED:** CS1705 — `Microsoft.AspNetCore` requires `System.Runtime 9.0.0.0` but Unity's Mono Editor only has `System.Runtime 4.1.2.0` (netstandard2.1 level)
- Root cause: ASP.NET Core 9 is fundamentally incompatible with Unity's Editor Mono runtime

### Solution: Switch from Grpc.AspNetCore to Grpc.Core
`Grpc.AspNetCore` requires .NET 9 runtime. Unity's compilation pipeline uses .NET Standard 2.1.
**Decision:** Rewrite `GrpcServerHost.cs` to use `Grpc.Core` (deprecated but netstandard2.0 compatible).

New `GrpcServerHost.cs`:
```csharp
_server = new Grpc.Core.Server {
    Services = { GameController.GameControllerService.BindService(new IoTGameServiceImpl()) },
    Ports = { new ServerPort("0.0.0.0", port, ServerCredentials.Insecure) }
};
_server.Start();
```

Delete from `Assets/Plugins/grpc/`:
- All `Microsoft.AspNetCore.*`
- All `Microsoft.Extensions.*`
- `Grpc.AspNetCore.Server.dll`
- `Grpc.Net.*.dll`

### Final DLL setup (working for compilation)

**Get managed DLLs (netstandard2.0) from NuGet cache:**
```powershell
# Google.Protobuf (netstandard2.0)
$ver = (ls "$env:USERPROFILE\.nuget\packages\google.protobuf\" | Select -Last 1).Name
Copy-Item "$env:USERPROFILE\.nuget\packages\google.protobuf\$ver\lib\netstandard2.0\Google.Protobuf.dll" "Assets\Plugins\grpc\"

# Grpc.Core.Api (netstandard2.0)
$ver = (ls "$env:USERPROFILE\.nuget\packages\grpc.core.api\" | Select -Last 1).Name
Copy-Item "$env:USERPROFILE\.nuget\packages\grpc.core.api\$ver\lib\netstandard2.0\Grpc.Core.Api.dll" "Assets\Plugins\grpc\"

# Grpc.Core managed DLL (netstandard2.0)
$ver = (ls "$env:USERPROFILE\.nuget\packages\grpc.core\" | Select -Last 1).Name
Copy-Item "$env:USERPROFILE\.nuget\packages\grpc.core\$ver\lib\netstandard2.0\Grpc.Core.dll" "Assets\Plugins\grpc\"

# Grpc.Core native binary (x64)
Copy-Item "$env:USERPROFILE\.nuget\packages\grpc.core\$ver\runtimes\win-x64\native\grpc_csharp_ext.x64.dll" "Assets\Plugins\grpc\"
```

**Unity Inspector settings:**

| DLL | Editor ✓ | Define Constraint | Notes |
|-----|----------|-------------------|-------|
| `Google.Protobuf.dll` | ✓ | — | needed for Generated/ always |
| `Grpc.Core.Api.dll` | ✓ | — | needed for Generated/ always |
| `Grpc.Core.dll` | ✓ | `UNITY_SERVER` | server only |
| `grpc_csharp_ext.x64.dll` | ✓ | — | native; CPU: x86_64 |

> **Note:** In Unity 6 Build Profiles, the `Server` platform checkbox does not appear in the
> plugin Inspector. Use **Define Constraints** instead. With all platform checkboxes unchecked
> + a define constraint, Unity excludes the DLL regardless — you must also check a platform.
> Workaround: check **Editor** + add `UNITY_SERVER` define constraint.

## Unsolved Problems — RESOLVED (see session 2025-04-25)

### `DllNotFoundException: grpc_csharp_ext` in server build — RESOLVED
**Fix:** Rename `grpc_csharp_ext.x64.dll` → `grpc_csharp_ext.dll` before placing in
`Assets/Plugins/grpc/`. Unity fails to recognize the native plugin with the `.x64`
infix in the filename. Removing it makes Unity pick it up correctly.

--- original notes below ---
The dedicated server build crashes at startup:
```
DllNotFoundException: grpc_csharp_ext assembly:<unknown assembly> type:<unknown type> member:(null)
  at Grpc.Core.Internal.NativeExtension..ctor()
  at Grpc.Core.GrpcEnvironment.GrpcNativeInit()
  at Grpc.Core.Server..ctor()
  at Server.GrpcServerHost.Start()
  at Server.ServerBootstrap.Start()
```

**What was tried:**
1. Copied `grpc_csharp_ext.x64.dll` next to the `.exe` — no effect
2. Copied to `ATITProject_Data\Plugins\x86_64\` — still fails
3. Inspector CPU set to `x86_64` (Unity's folder name) — DLL still not auto-copied by build

**Build output structure:**
```
ATIT Build/
  ATITProject.exe
  ATITProject_Data/
    Managed/       ← managed DLLs are here
    Plugins/
      x86_64/
        lib_burst_generated.dll   ← only this, grpc_csharp_ext NOT here
  MonoBleedingEdge/
```

**Hypothesis:** The Inspector CPU setting `x86_64` may not be the correct value, or the
platform setting is not correctly targeting the server build, so Unity doesn't copy the DLL
during build. Needs further investigation next session.
